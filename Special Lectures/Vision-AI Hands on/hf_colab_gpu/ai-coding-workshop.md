# 완성된 핵심 코드 읽고 조건 바꾸기

01번과 02번의 핵심 함수는 **각각 두 개씩, 모두 완성된 코드로 제공**합니다. 00번으로 모델과 데이터를 준비한 뒤 01·02를 실행합니다. 별도로 답안을 작성하거나 강사용 파일을 받을 필요 없이 같은 노트북에서 코드 읽기·결과 확인·조건 변경을 이어갑니다.

## 실행 순서

1. Codespaces에서 00번 노트북으로 모델과 데이터를 준비합니다.
2. `01_gpu_inference.ipynb`와 `02_gpu_finetuning.ipynb`의 함수 설명과 예상 출력 형태를 읽습니다. 처음에는 코드를 바꾸지 않고 실행합니다.
3. GPU를 만들기 전에 프로젝트 최상위 터미널에서 아래 검사를 실행합니다.

```bash
source .venv/bin/activate
python scripts/check_student_cells.py
```

이 검사는 GPU를 사용하지 않으며 제공된 함수와 Python 문법을 확인합니다. 계산 결과까지 보장하지는 않으므로 실제 실행 뒤 노트북 안의 확인 결과도 읽습니다. 코드를 수정했다면 **입력 노트북을 저장**하고 같은 검사를 다시 실행합니다. 다른 위치에 저장했다면 노트북 경로를 인자로 지정할 수 있습니다.

```bash
python scripts/check_student_cells.py \
  hf_colab_gpu/notebooks/01_gpu_inference.ipynb \
  hf_colab_gpu/notebooks/02_gpu_finetuning.ipynb
```

검사를 통과한 뒤 [실행 안내](README.md)의 Google 로그인·GPU 세션 생성·라이브러리 설치·파일 전송을 진행합니다. Codespaces CPU 커널의 Run All은 Colab GPU에 자동으로 연결되지 않습니다. 01·02의 실제 GPU 실행은 다음 CLI 명령으로 진행합니다.

```bash
colab exec -s hf-vision-gpu -f hf_colab_gpu/notebooks/01_gpu_inference.ipynb --timeout 1800
```

01번의 출력 노트북에서 **모든 코드 셀에 오류가 없는지** 확인한 뒤 02번을 실행합니다.

```bash
colab exec -s hf-vision-gpu -f hf_colab_gpu/notebooks/02_gpu_finetuning.ipynb --timeout 1800
```

`colab exec -f`는 코드 셀을 이어서 실행합니다. 셀 오류가 있어도 CLI가 뒤의 셀을 계속 실행할 수 있으므로 명령 종료만으로 성공을 판단하지 않습니다.

## 네 함수에서 확인할 것

| 노트북 | 함수 | 코드의 처리 순서 | 실행 뒤 볼 결과 |
|---|---|---|---|
| 01 · 이미지 추론 | `infer_probabilities` | 전처리 → 지정 장치로 이동 → 추론 모드에서 클래스 확률 계산 | 확률의 개수·합·범위, 실제 이미지의 예측 |
| 01 · 예측 순위 | `topk_predictions` | 점수가 높은 순서로 `k`개 선택 → 라벨 이름 연결 | Top-1·Top-3 비교, 최종 Top-5 표와 그림 |
| 02 · 한 배치 학습 | `train_one_batch` | 기존 기울기 초기화 → 예측 → 손실 → 역전파 → 갱신 | 반환한 손실·정답 수·개수, 학습 손실과 정확도 |
| 02 · 학습 범위 | `select_finetune_parameters` | 전체 고정 → `head` 또는 `last_block` 범위만 학습 대상으로 선택 | 대상 이름·개수, 학습 곡선·혼동행렬 |

각 함수의 입력과 반환 형식, 사용하는 변수와 확인 코드는 노트북에 있습니다. 코드가 낯설다면 [초보자용 해설 노트북](explanations/README.md)을 함께 읽습니다.

## 한 번에 하나씩 바꿔 보기

- **01번:** `k=1`과 `k=3`일 때 어떤 후보가 보이는지 비교합니다. 최종 보고서는 기존처럼 Top-5를 저장합니다. 후보 수가 늘어나는 것과 모델 예측 자체가 바뀌는 것은 구분합니다.
- **02번:** 학습 범위가 `head`일 때와 `last_block`일 때 대상 파라미터가 어떻게 달라지는지 확인합니다. 이번 고정 모델의 5개 클래스 설정에서는 각각 **965개**, **446,213개**입니다. 범위를 비교한 뒤 실제 두 번째 학습은 `last_block`으로 진행합니다.
- **작은 학습 실험:** 02번의 연습 모델에서는 학습률 `0.01`과 `0.1`로 두 번씩 학습해 손실을 비교합니다. 실제 DeiT 모델의 가중치와 본학습 설정은 바꾸지 않는 짧은 실험입니다.
- **결과 설명:** 어떤 확인 셀이 통과했는지, 예상과 실제 출력이 어디서 달랐는지 적습니다. 정확도가 올라가도 모든 클래스가 함께 좋아졌는지 혼동행렬에서 다시 확인합니다.

숫자를 바꾸기 전에 의미와 예상 결과를 적습니다. 학습률·epoch까지 바꾸는 추가 실험은 기본 실행을 마친 뒤 별도 결과 폴더에서 진행합니다.

AI를 사용하지 않아도 제공된 코드로 실습을 마칠 수 있습니다. 설명이 필요하다면 다음처럼 요청합니다.

> 아래 함수의 입력과 반환값, 각 줄의 역할을 초보자에게 설명해 줘. 코드는 바꾸지 말고, `k`를 1에서 3으로 바꾸었을 때 출력이 어떻게 달라질지 먼저 예상해 줘.

코드를 바꾼 뒤 확인 셀에서 실패했다면 오류 메시지와 해당 함수, 지켜야 할 입력·출력 조건을 함께 전달합니다.

> 이 함수를 수정한 뒤 아래 확인 셀에서 실패했어. 원인을 먼저 설명하고, 함수 이름과 입력·반환 형식을 유지한 수정 코드를 제안해 줘. 확인 코드를 지우거나 결과 숫자를 직접 넣는 방식은 사용하지 마.

수정한 입력 노트북을 저장하고 사전 검사부터 다시 진행합니다. 02번을 완주한 뒤 재실행할 때는 기존 결과를 덮어쓰지 않도록 막혀 있습니다. 노트북 안내에 따라 새 결과 폴더를 정하거나 기존 결과를 보관한 뒤 실행합니다. 오류 해결을 위해 결과 파일을 무조건 삭제하지 않습니다.

## 남길 기록과 종료

각 실험마다 **바꾼 조건 → 예상 → 실제 결과 → 해석 한 문장**을 남깁니다. AI에게 도움을 받았다면 사용한 프롬프트도 덧붙입니다.

기존 검증 문서의 T4 정확도 80% → 81%는 **2026-09-19에 실행한 코드의 기록**입니다. 완성 코드를 제공하도록 바꾼 뒤 새로 측정한 GPU 결과가 아닙니다. 본인의 결과와 나란히 비교하되 그대로 복사하지 않습니다.

결과 파일과 출력 노트북을 회수한 뒤 이번에 만든 Colab 세션을 종료하고 종료 여부를 확인합니다. Codespaces도 별도로 중지합니다. 도중에 실습을 중단했더라도 GPU 세션 종료가 필요합니다.
